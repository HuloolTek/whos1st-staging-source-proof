# WHO’S 1ST? — Staging ownership-verification procedure

**Purpose:** This is a public, staging-only GitHub repository controlled by HuloolTek. It is used to test genuine source-ownership challenges. It is not the WHO’S 1ST? product source repository and is not connected to production, Vercel, Stripe, or any payment-controller account.

## Verification procedure

1. In the **SSO-protected WHO’S 1ST? staging application only**, begin a source-ownership request for the exact GitHub repository URL, **if the application supports that source type and verification method**. Do not assume GitHub ownership verification is automatic. If the current implementation does not support it, document that limitation and stop.
2. Obtain a **real, fresh challenge** generated by the staging application's existing verification workflow. Never invent a challenge, receipt, moderator decision, source grant, or controller record.
3. An authorized HuloolTek repository maintainer publishes **only the required non-secret proof** at the specific location prescribed by the supported verifier. Any future proof file should be clearly marked as temporary staging QA. Do not publish passwords, tokens, signed credentials, private contact data, or customer information.
4. A separate authorized moderator reviews the actual issued challenge, public proof, source identity, expiration and audit trail, using the established operator process. Source verification must not by itself confer Paid Power or payment-controller rights.
5. Test permitted and denied actions via the existing staging policies. Any Updates must comply with the product's eligible-source rules and moderation requirements. The repo itself is not authorization to impersonate a verified entity.
6. After acceptance, remove temporary proof artifacts and QA records according to the approved cleanup procedure. Disable any staging-only write gates and retain only the required audit evidence.

**Important limits:** Do not connect this repository to GitHub Actions secrets, the production WHO’S 1ST? repository, production DNS, live Stripe, or production Supabase. Official replies require legitimate payment-verified listing-controller authority, separate from this source proof.

No verification challenge has been requested or published by this document.
